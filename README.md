# Pechatniky — sitio de pedidos + panel de administración

Sitio de pedidos de comida (estilo cafetería con entrega) más el panel para
administrarlo. Интерфейс — на испанском, комментарии в коде — на русском.

Dos partes:
- **Tienda pública** (`/`) — el cliente ve el menú y hace su pedido. Sin
  registro ni contraseña: escribe sus datos a mano en cada pedido.
- **Panel de administración** (`/admin`, `/pedidos`, `/ajustes`) — gestión de
  platos, categorías, tipo de cambio y pedidos entrantes. Protegido por
  contraseña.

## 🚀 Релиз: запуск и эксплуатация (актуально)

**Запуск без pm2:** `npm install` → `node server.js` (порт по умолчанию 80, если нет прав — автоматически 3000; свой порт: `PORT=3000 node server.js`).
`server.js` сам себя «присматривает»: рабочий процесс запускается как дочерний, при падении перезапускается (пауза 1→30 с). Ошибки не роняют сервер, пишутся в `logs/server.log` (ротация 2 МБ) и (если включено) приходят в Telegram. Если порт занят или конфиг неверный — понятное сообщение, без бесконечных перезапусков. `NO_SUPERVISOR=1` отключает супервизор (если запускаете под systemd/pm2).
Проверка живости: `GET /health`.

**Переменные окружения:** `PORT`, `SESSION_SECRET` (иначе генерируется и хранится в `data/secret.txt`), `TRUST_PROXY` (за nginx/Cloudflare), `NO_SUPERVISOR`, `TELEGRAM_API_BASE` (для тестов).

**Вход админа:** отдельной страницы логина нет. Админ входит через обычную форму «Mi cuenta» магазина: в поле email пишет `admin`, затем пароль панели. После входа вверху магазина появляется кнопка панели (видна только ему, в публичном HTML ссылки на админку нет). Страницы `/admin`, `/pedidos` и др. без сессии админа перенаправляют на магазин.

**Сессии** хранятся в `data/sessions.json` — перезапуск сервера никого не разлогинивает (30 дней). Пароли — как есть, открытым текстом (по решению владельца).

**Всё настраивается в админке → Ajustes** (секции): Tienda (название, эмодзи, слоган, объявление), Contactos (всегда сверху сайта), Horario (часы по дням, часовой пояс, ручное закрытие, приём заказов вне часов → «доставим завтра»), Pedidos y pagos (минимум, бесплатная доставка, время, способы оплаты, порог «Quedan N»), курс и доставка по municipio, категории, Apariencia (9 тем; тема магазина по умолчанию), **Telegram**, **Copias de seguridad**, пароль панели и звук новых заказов.

**Telegram:** @BotFather → `/newbot` → токен вставить в Ajustes → Telegram → Guardar → «Abrir el bot y vincular» (или `/start КОД`). Бот шлёт уведомления по всем событиям (включаются по отдельности) и имеет меню `/menu`: новые/активные заказы со статус-кнопками, статистика, склад (скрыть/показать блюдо), открыть/закрыть магазин, бэкап, настройка уведомлений, `/estado`, `/desvincular`.

**Бэкапы:** папка `backups/` (данные + по желанию фото), частота/кол-во хранимых — в Ajustes; скачивание ZIP из админки. Если JSON-файл повреждён, при старте он восстанавливается из последней копии (битый сохраняется как `*.corrupto-*`). Ручное восстановление: остановить сервер, скопировать файлы из копии в `data/`.

**Новое для клиентов:** номера заказов, экран подтверждения, защита от двойного нажатия (идемпотентность), «Pedir de nuevo», остатки блюд (Agotado / Quedan N), состояние сети (баннер + повтор), PWA (установка, офлайн-оболочка), мета-теги (OG, JSON-LD), ленивые картинки, смена пароля, темы. **Для админа:** редактирование заказа, фильтры/поиск заказов и блюд, остатки (с ежедневным обновлением), статистика (`/estadisticas`), звук о новом заказе.

**Название вкладки и иконка сайта** меняются в Ajustes → Tienda (иконка из одной картинки превращается в favicon, иконку PWA, apple-touch и превью для соцсетей; хранится в `public/uploads/icono/`). **Мигающий заголовок:** при новых заказах (админ) и изменениях в заказах клиента заголовок вкладки мигает «🔔 …», а на иконке вкладки появляется красный счётчик. **Печать тикета** заказа (кнопка «Imprimir» в карточке) и **экспорт заказов в CSV** (страница статистики).

**QR-код сайта:** в админке кнопка QR (или `/qr`) — 8 дизайнов, 3 формата (пост, квадрат, история), свои тексты, логотип в центре, контакты и ссылка; скачивание PNG и «Compartir» с телефона. Генерация целиком в браузере (библиотека лежит в `public/vendor/qrcode`).

**Бэкап в Telegram:** Ajustes → Copias de seguridad → «Enviar copia a mi Telegram» + частота (1 ч … неделя). Бот присылает ZIP с данными (заказы, клиенты, блюда, настройки; без фото, лимит Telegram 50 МБ) всем привязанным чатам; кнопка «Enviar ahora» и команда `/backup` в боте шлют копию сразу. При ошибке повтор через час. Внимание: в ZIP лежат и данные доступа (пароль админа, токен бота) — храните чат приватным.

**Ограничение:** у клиентов без доступа к email нет самообслуживаемого сброса пароля — владелец правит пароль в `data/clientes.json`.

## Стек
- Backend: Node.js + Express, express-session (авторизация по cookie), multer + jimp (загрузка и сжатие изображений — `jimp` работает без нативных бинарников, ставится одинаково на любой платформе)
- Frontend: чистый JS, HTML, CSS (без фреймворков)
- Хранение данных: JSON-файлы в папке `data/` (без базы данных)
- Изображения блюд: файлы в `public/uploads/productos/`
- Шрифты: **только системные** (`-apple-system, Segoe UI, Roboto, Helvetica Neue, Arial`) —
  никаких внешних подключений к Google Fonts, ничего не грузится по сети для
  текста, страница отрисовывается сразу, без ожидания загрузки шрифта.
- Карта (для выбора точки доставки): **Leaflet**, файлы лежат локально в
  `public/vendor/leaflet/` (не через CDN, без ключа API, без карты и
  регистрации где-либо) — грузится только на странице магазина. Сами тайлы
  карты всё равно приходят через интернет с OpenStreetMap — это неизбежно
  для любой карты, а вот сам код библиотеки не зависит от внешнего хостинга.

## Запуск

```bash
npm install
npm start
```

Сервер по умолчанию слушает **порт 80** — на macOS/Linux для этого обычно нужны
права администратора:

```bash
sudo npm start
```

Порт можно переопределить переменной окружения (например, при разработке,
чтобы не требовать sudo):

```bash
PORT=3000 npm start
```

- Магазин для клиентов: `http://localhost/`
- Панель администратора: `http://localhost/admin` (перенаправит на `/login`, если не авторизован)

**Пароль по умолчанию:** `cafeteria2026` — задан в `data/users.json` (см. раздел «Авторизация» ниже).
Обязательно смени его перед реальным использованием. Секрет сессии — через переменную окружения:

```bash
SESSION_SECRET=случайная_строка npm start
```

## Авторизация

Пользователи хранятся в `data/users.json`, каждый — со своим паролем и
персональной темой оформления:

```jsonc
[
  { "id": "admin", "usuario": "admin", "password": "cafeteria2026", "tema": "oscuro" }
]
```

При входе введённый пароль ищется среди всех пользователей; если находится
совпадение — создаётся cookie-сессия (`express-session`, httpOnly) и
запоминается, какой именно пользователь вошёл. Форма входа сейчас спрашивает
только пароль (без логина) — этого достаточно, пока пользователей мало и
пароли не пересекаются.

Пока сессия жива (по умолчанию неделю), `/admin`, `/ajustes`, `/pedidos` и все
защищённые `/api/*` маршруты доступны; без сессии — редирект на `/login` (для
страниц) или `401` (для API). **Магазин (`/`) и `/api/public/*` открыты всем —
авторизация там не нужна**, клиент оформляет заказ, просто указав свои данные
в форме.

**Пароли хранятся в открытом виде** — это временное упрощение для внутреннего
инструмента на раннем этапе, не для продакшена с чувствительными данными
(см. TODO про хеширование).

## Тема оформления (тёмная/светлая)

Хранится в `users.json`, привязана к конкретному пользователю: у каждого может
быть своя тема. Переключается в **Ajustes → Apariencia**; переключатель сразу
применяет тему на странице и сохраняет её на сервере, так что при следующем
входе (в том числе с другого устройства) будет использована та же тема.
Технически это CSS-переменные с атрибутом `data-theme` на `<html>`; шапка
(topbar) всегда остаётся тёмной — это фирменный элемент, не завязанный на тему.
Магазин для клиентов пока всегда тёмный (тема привязана к пользователю
админки, а у клиента пользователя нет).

## Цены и валюта

Цены товаров хранятся и вводятся **в кубинских песо (CUP)**. Курс обмена
(«сколько CUP за 1 USD») задаётся вручную на странице **Ajustes** и хранится в
`data/settings.json`. Везде, где показывается цена блюда, рядом выводится цена
в долларах — отредактировать её напрямую нельзя: она всегда пересчитывается из
цены в CUP и текущего курса, **округляясь вверх до целого числа** (например,
850 CUP при курсе 380 → $3, а не $2.24). Это не приблизительная оценка «около
такой-то суммы» — округлённое значение и есть окончательная цена в долларах,
поэтому рядом с ней не ставится знак «≈».

## Изображения блюд

Клик по фото товара открывает его в полный размер в новой вкладке (и в
магазине, и в панели администратора).

Все загружаемые изображения **сильно сжимаются на сервере** (через `jimp` —
библиотеку обработки изображений на чистом JS, без нативных бинарников, чтобы
не было проблем с установкой на разных платформах) — это осознанный компромисс
в пользу скорости загрузки на слабом интернете:
- уменьшаются до `800×800` (вписываются в рамку, не растягиваются, если и так меньше);
- перекодируются в JPEG с качеством 60;
- сохраняются всегда с расширением `.jpg`, независимо от исходного формата
  (JPG/PNG/WEBP/GIF на входе — животированные GIF превращаются в статичный кадр);
- ориентация фото с телефона (EXIF-тег `Orientation`) считывается и применяется
  вручную, чтобы фото не оказалось «лежащим на боку» — учитываются самые частые
  случаи поворота (90°/180°/270°); редкие зеркальные варианты EXIF не
  обрабатываются, но встречаются крайне редко на практике.

Итоговый файл весит в разы меньше оригинала (проверено на тестовом изображении:
~4 МБ на входе → уменьшение в несколько раз, конкретная степень сжатия зависит
от содержимого фото — у настоящих фотографий блюд сжатие обычно намного
эффективнее, чем у случайного шума).

## Вес/объём и лимит на заказ

У блюда можно (не обязательно) указать:
- **Вес или объём порции** — число + единица (`g`, `kg`, `ml`, `l`), например «350 g»;
- **Максимум в одном заказе** — целое число; если не задано, ограничения нет.

Оба поля хранятся в `products.json` (`porcion: { valor, unidad } | null` и
`maximoPorPedido: number | null`).

В магазине для клиента число максимума **нигде не показывается заранее** —
ни в карточке в списке, ни в детальном экране блюда (раньше была надпись
«Máx. N/pedido» в обоих местах, её убрали). Кнопка «+» в счётчике количества
тоже больше не отключается заранее по достижении лимита — она остаётся
активной, и лимит применяется по факту: попытка добавить ещё одну единицу
сверх максимума просто не проходит, и в этот момент показывается понятный
тост («Ya tienes el máximo permitido de "…" en tu pedido (N).») — клиент
узнаёт о лимите только тогда, когда реально в него упирается, а не заранее.
Тот же принцип — при открытии магазина: если в сохранённой корзине
(`localStorage`) количество какого-то блюда оказывается больше текущего
максимума (например, админ его снизил уже после того как клиент добавил
блюдо в корзину в прошлый визит), `sanearCarrito()` уменьшает количество до
нового максимума и тоже показывает тост об этом — это тот самый случай «уже
в корзине обнаружили, что количество больше максимального», ради которого и
задумана эта логика. Панель администратора (`admin.js`) продолжает
показывать «Máx. N/pedido» как обычно — это её собственный список товаров,
где эта информация уместна.

## Магазин для клиентов

Открыт на `/`. Смотреть каталог может кто угодно, **но оформить заказ можно
только с аккаунтом** (см. ниже) — если нет сессии, кнопка корзины и кнопка
«Mis pedidos» ведут прямо на вход/регистрацию, а не показывают форму заказа
или пустую историю понапрасну. Раньше можно было заказать и без регистрации,
указывая все данные вручную — от этого отказались, чтобы «Mis pedidos» и
отмена заказа работали одинаково для всех заказов, без исключений для гостей.

- Каталог показывает только доступные блюда (`disponible: true`), с фильтром
  по категориям и **поиском по названию и описанию** (поле поиска — тот же
  визуальный компонент `.searchbar`, что и в панели администратора для поиска
  товаров, только здесь он всегда виден, а не спрятан за кнопкой). Поиск и
  фильтр по категории работают вместе — например, можно выбрать «Almuerzos» и
  дополнительно сузить список поиском.
- Нажатие на **любую часть карточки** товара (не только на фото) открывает
  детальный экран блюда: фото покрупнее — **прямоугольное (16:9), не
  квадратное**, чтобы не занимать пол-экрана (по-прежнему кликабельное —
  открывает оригинал во весь размер в новой вкладке) — и **полное** описание
  без обрезки (в самой карточке списка описание всё ещё обрезается
  многоточием, чтобы список оставался компактным). Кнопка «Agregar»/счётчик
  количества работает и там, и там одновременно — при изменении обновляются
  обе копии. Клик по счётчику количества внутри карточки не открывает
  детальный экран (у него своя область клика).
- При оформлении заказа можно (необязательно) **отметить точку на карте**
  для доставки — см. раздел «Ubicación en el mapa» ниже.
- Корзина хранится в `localStorage` браузера клиента (не на сервере) — переживает
  обновление страницы, но не переносится на другое устройство. Собирать
  корзину можно и без сесии — сессия нужна только в момент оформления.
- При оформлении заказа форма приходит уже заполненной именем/телефоном/адресом
  из аккаунта (см. «Mi perfil» ниже), но их можно поправить перед отправкой —
  например, если доставка в этот раз на другой адрес. Никакого способа оплаты
  пока не спрашивается (см. TODO).
- Сервер никогда не доверяет цене или названию, присланным из браузера: и то,
  и другое, а также итоговую сумму, всегда берёт из текущего каталога на
  сервере — это же значение «замораживается» в заказе на будущее (если позже
  изменить цену блюда, уже оформленный заказ сохранит цену на момент заказа).
- `POST /api/public/orders` теперь требует сессию клиента (`401`, если её
  нет) — см. раздел API ниже.

## Аккаунт клиента (обязателен для заказа)

Кнопка «👤» в шапке магазина открывает вход/регистрацию. Логин — **email +
пароль**. Телефон при регистрации тоже обязателен, но это просто контактные
данные для доставки — по нему больше нельзя войти (раньше было наоборот:
логином был телефон, а email не спрашивался вообще).

**Solo el email no se puede cambiar después del registro** — es el
identificador de la cuenta (con el que se inicia sesión), así que en «Mi
perfil» se muestra bloqueado (`disabled`, atenuado visualmente). El
**teléfono sí se puede editar** desde «Mi perfil» (por ejemplo, si el
cliente cambió de número) — antes también estaba bloqueado, pero eso
resultaba demasiado rígido para un dato que cambia con más frecuencia que el
email. Esto no es solo una restricción de interfaz: el validador del
servidor para actualizar el perfil (`validatePerfil` en
`src/validators/clientes.js`) **ni siquiera lee** `email` del cuerpo de la
petición — aunque se mande directo por API sin pasar por el formulario, la
ruta `PUT /api/public/me` no lo ve ni lo guarda. Si de verdad hace falta
cambiar el email de una cuenta, solo queda hacerlo a mano en
`data/clientes.json` (ver TODO).

**Без какого-либо подтверждения** — указал email, телефон и пароль (минимум 4
символа) и аккаунт сразу активен. Это осознанно самый простой вариант:
подтверждение по email потребовало бы стороннего сервиса рассылки (Brevo,
Mailjet и т. п.), подтверждение по SMS — платного шлюза (например, Twilio) —
оба варианта требуют дополнительной инфраструктуры, которой сейчас нет. Как и
с паролями администратора, это временное упрощение (см. TODO про хеширование
и подтверждение).

Без аккаунта нельзя оформить заказ вообще (см. выше), а с ним доступно:
- Данные (имя, телефон, адрес) один раз сохраняются и автоматически
  подставляются в форму заказа при следующих визитах (их всё ещё можно
  отредактировать перед отправкой).
- Своя иконка **«Mis pedidos»** в шапке магазина (отдельная от «👤», со своим
  bottom sheet, не смешанным с формой входа/профиля) — показывает историю
  заказов клиента с их текущим статусом, так клиент видит, готовится ли его
  заказ, без обращения к администратору.
  Рядом с иконкой — **наклейка-счётчик открытых (не завершённых) заказов**:
  считает всё, что ещё не в статусе `completado`/`cancelado` (то есть `nuevo`,
  `en_preparacion` или `enviado`); опрос `GET /api/public/mis-pedidos` каждые
  15 секунд обновляет и счётчик, и тост при смене статуса (см. «Оповещения о
  заказах» ниже).
- Раздел «Mi perfil» (внутри «Mi cuenta», отдельно от «Mis pedidos») позволяет
  сменить **имя, телефон и адрес по умолчанию**, которые подставляются в форму
  заказа (email менять нельзя, см. выше). А также переключатель **тёмная /
  светлая тема** — работает так же, как в админке (`Ajustes → Apariencia`), но
  хранится отдельно для каждой учётной записи клиента (`data/clientes.json`,
  поле `tema`), независимо от темы администратора.

Технически это отдельная лёгкая сессия (`req.session.clienteId`), не связанная
с сессией администратора (`req.session.autenticado`) — обе спокойно уживаются
в одной cookie, если, например, зайти и в магазин, и в панель с одного
браузера.

## Municipio y costo de envío (доставка по муниципалитетам Гаваны)

Первая версия этой функции моделировала выбор как «provincia» (провинцию
Кубы, каких 16 на всю страну) — но бизнес доставляет только **внутри
Гаваны**, так что выбор провинции не имел смысла: реальная зона и стоимость
доставки определяются **муниципалитетом Гаваны** (La Habana Vieja, Centro
Habana, Playa и т. д. — их 15). Модель поправлена по итогам обратной связи:
`provincia` заменена на `municipio` по всему коду (конфиг, валидаторы, роуты,
оба фронтенда).

При оформлении заказа клиент **обязан выбрать municipio** из выпадающего
списка. Список муниципалитетов захардкожен в `src/config.js`
(`MUNICIPIOS_HABANA`) и продублирован на клиенте (`tienda.js`, `ajustes.js`)
— на сервере это источник истины, клиентские копии только для интерфейса.
В отличие от прежней версии с провинциями (где только одна была разрешена, а
остальные 15 показывались как «próximamente»), **все 15 муниципалитетов
можно выбрать** — бизнес и так развозит по всему городу, а меняется от
муниципалитета к муниципалитету только стоимость доставки.

Сервер **не доверяет** municipio, присланному с клиента: `POST
/api/public/orders` проверяет, что это существующий id муниципалитета из
списка (иначе `400` с понятным сообщением) — защита на случай, если кто-то
соберёт запрос напрямую, в обход `<select>` на странице.

**Тариф доставки по каждому муниципалитету** задаётся в панели
администратора, **Ajustes → Envío por municipio** — по одному полю (в CUP)
на каждый из 15. Хранится в `data/settings.json` (`enviosPorMunicipio: {
[municipioId]: number }`) — муниципалитеты, для которых тариф ещё не
задавали, автоматически считаются равными `0` и так же показываются в форме
(`conEnviosCompletos()` в `src/routes/ajustes.js` дозаполняет отсутствующие
ключи при каждом чтении/записи, а не только при показе, так что и
сохранённый на диске файл, и то, что видит клиент через `GET
/api/public/menu`, всегда содержат все 15 муниципалитетов). Старое поле
`enviosPorProvincia` из предыдущей версии `settings.json`, если такое
осталось на диске, автоматически отбрасывается при первом же чтении/записи
настроек — миграция вручную не нужна.

Как и с ценой блюд, стоимость доставки **замораживается в заказе на момент
его создания** (`envioCup`, вычисляется на сервере как
`enviosPorMunicipio[cliente.municipio]` из текущих Ajustes и сохраняется в
заказе) — если админ позже поменяет тариф, уже оформленные заказы сохранят
ту стоимость доставки, что действовала в момент заказа. Итоговая сумма заказа
(`totalConEnvioCup = totalCup + envioCup`) показывается клиенту и в форме
заказа (отдельными строками — Subtotal / Envío / Total — в
`.carrito-resumen`), и в истории «Mis pedidos», и админу на странице
**Pedidos** (там же рядом с контактами показывается название муниципалитета).

Обновление настроек (`PUT /api/settings`) делает честный read-patch-write по
существующему файлу, а не полную перезапись — сохранение курса CUP/USD не
стирает тариф доставки, и наоборот.

## Отметка на карте (обязательна, только Гавана)

При оформлении заказа, помимо ручного ввода адреса, клиент **обязан** нажать
кнопку «📍 Marcar ubicación en el mapa» и отметить точку доставки на карте —
это дополнение к написанному адресу, а не замена (текстовое поле
по-прежнему тоже обязательно). Раньше это было необязательно — теперь без
отмеченной точки заказ не отправляется вообще: и клиентская валидация формы
(`el.formPedido` в `tienda.js`), и серверная (`validateUbicacion` в
`src/validators/pedidos.js`) требуют `cliente.ubicacion` — раньше это поле
принимало `null`, теперь `null`/отсутствие координат отклоняется с `400`
(«Marca tu ubicación en el mapa.»).

- Карта (**Leaflet**, см. «Стек») центрирована на Гаване и **не даёт
  отдалиться или выехать за пределы города** (`maxBounds` +
  `maxBoundsViscosity: 1.0`), потому что бизнес доставляет только там. Тап
  ставит/двигает маркер; чтобы сохранить точку, нужно нажать «Confirmar
  ubicación».
- Кнопка **«📍 Usar mi ubicación actual»** над картой использует
  `navigator.geolocation.getCurrentPosition()` браузера, чтобы найти клиента
  автоматически — не нужно искать себя на карте вручную. Найденная точка
  центрирует карту и сразу ставит маркер (после этого её всё ещё можно
  подвинуть тапом, если GPS немного промахнулся, и всё равно нужно нажать
  «Confirmar ubicación», чтобы она сохранилась). Если точка оказывается за
  пределами Гаваны, координата отклоняется с понятным тостом («ubicación
  actual parece estar fuera de La Habana»), вместо того чтобы молча поставить
  маркер не пойми где. Если браузер не поддерживает геолокацию, доступ к ней
  запрещён пользователем, определить местоположение не удалось или запрос
  превысил таймаут (8 сек.) — в каждом случае свой понятный тост, а клиент
  всегда может просто тапнуть нужную точку на карте вручную.
- Маркер — это **встроенный SVG** (`L.divIcon`, см. `tienda.js`), а не
  дефолтный набор из трёх PNG-файлов Leaflet (`marker-icon.png`,
  `marker-icon-2x.png`, `marker-shadow.png`). Так надёжнее: иконка едет прямо
  внутри JS, ей не нужен отдельный файл, который может не найтись (именно
  это и было — 404 на `marker-shadow.png`). "Тень" маркера — это CSS
  `drop-shadow`, а не отдельная картинка.
- Координаты (`{ lat, lng }`) едут в `cliente.ubicacion` заказа — сервер
  **повторно проверяет**, что они попадают в прямоугольник Гаваны
  (`HABANA_BOUNDS` в `src/config.js`), прежде чем сохранить заказ, не
  доверяя тому, что карта в браузере их уже ограничила (`400`, если точка
  снаружи).
- Отметка действует **только для одного заказа** — в профиль клиента она не
  сохраняется, так что при следующем заказе её нужно ставить заново (обязательно
  и тогда).
- Админ видит ссылку «📍 Ver ubicación en el mapa» на карточке заказа
  (страница **Pedidos**), если клиент её отметил — открывает OpenStreetMap с
  этой точкой в новой вкладке.
- Плюс, если удалось, **небольшую подписанную «карточку»** с примерным
  адресом в виде текста (например «Calle 23, Vedado, La Habana, Cuba»),
  прямо под контактами клиента (`.pedido__direccion-aprox` в стилях). Это
  результат обратного геокодирования через бесплатный сервис Nominatim
  (OpenStreetMap) — **вызывается один-единственный раз, при создании заказа**
  (`src/lib/geocoding.js`, из `POST /api/public/orders`), и сразу сохраняется
  в самом заказе (`cliente.direccionAproximada`). Панель администратора
  ничего не запрашивает у Nominatim сама — просто показывает то, что уже
  сохранено. Если сервис не ответил вовремя (таймаут 4 сек.) или недоступен,
  поле остаётся `null` и карточка с адресом просто не показывается — заказ
  всё равно создаётся нормально, с точными координатами и ссылкой на карту.
- **Баг, найденный и исправленный при тестировании:** этот sheet — единственный,
  который открывается ПОВЕРХ уже открытого другого sheet (карточки заказа),
  но у обоих был одинаковый z-index, а `#sheetMapa` в HTML идёт раньше
  `#sheetCarrito` — значит, всё ещё открытый carrito-sheet перекрывал карту
  целиком (рисуется позже в DOM = сверху), и клик по кнопке визуально ничего
  не менял (без единой ошибки в консоли, потому что ошибки и не было — это
  была чистая проблема стека наложения). Исправлено явным `z-index` у
  `#overlayMapa` (45) и `.sheet--mapa` (50) в `styles.css`, выше базовых
  `.overlay`/`.sheet` (30/40). Проверено сквозным тестом в headless-браузере
  (Playwright): клик по кнопке → карта видна и кликабельна → маркер ставится →
  заказ с координатами доходит до сервера и проходит валидацию.
- Заодно тем же тестом нашёлся и исправлен независимый баг в карточке товара:
  клик по кнопке «Agregar» иногда всё равно открывал детальный sheet товара,
  потому что кнопка заменяет сама себя на степпер (+/−) во время своего же
  клика, и к моменту всплытия события до карточки исходная кнопка уже
  отсоединена от DOM — проверка `e.target.closest('.tarjeta__acciones')`
  переставала находить родителя. Исправлено через `e.composedPath()`
  (сохраняет путь события на момент клика, а не на момент проверки) в
  `crearTarjetaProducto()` (`public/js/tienda.js`).

## Заказы и их статусы

Оформленный заказ сразу попадает в панель администратора, на страницу
**Pedidos** (доступна из шапки `/admin` и `/ajustes`).

Статусы заказа, в порядке движения:
1. **Nuevo** — заказ только что пришёл от клиента, ожидает внимания админа.
2. **En preparación** («В работу») — админ нажал кнопку и начал готовить заказ.
3. **Enviado** («Отправлен») — заказ выехал на доставку.
4. **Completado** («Завершен») — заказ доставлен и закрыт.

Админ продвигает заказ по одной кнопке за раз (каждая кнопка ведёт к
следующему статусу). Это намеренно простая, линейная схема статусов — без
возможности откатить статус назад (см. TODO).

Отдельно от этой цепочки есть терминальный статус **Cancelado**, с двумя
разными путями:
- **Клиент** может отменить свой заказ, только пока он ещё в статусе
  **Nuevo** — как только админ нажал «En preparación», кнопка отмены
  пропадает из магазина (`POST /api/public/orders/:id/cancelar`).
- **Админ** может отменить заказ в любом статусе цепочки **кроме
  «Completado»** — например, уже «Enviado» (если доставка сорвалась) — своей
  отдельной кнопкой «Cancelar pedido» на каждой карточке страницы **Pedidos**
  (`POST /api/orders/:id/cancelar` — отдельный эндпоинт от клиентского).
  «Completado» — второй терминальный статус наравне с «Cancelado»: заказ уже
  доставлен и закрыт, отменять «задним числом» нечего, поэтому у карточки в
  этом статусе кнопки «Cancelar pedido» просто нет (и сервер отклонит `400`,
  если запрос всё же придёт напрямую). Единственный другой отказ (тоже `400`)
  — попытка отменить уже отменённый заказ.

### Оповещения о заказах

Без веб-сокетов и настоящего push — это по-прежнему периодический опрос
(`setInterval`), пока страница открыта, но теперь с двумя уровнями:

- **Наклейка-счётчик** (сдержанная, на иконке в шапке): у админа — количество
  заказов в статусе `nuevo`; у клиента — количество **открытых** заказов
  (`nuevo` + `en_preparacion` + `enviado`). Обновляется сама, без каких-либо
  действий от пользователя.
- **Яркое уведомление, которое не пропадает само** (`public/js/alertas.js`) —
  крупный цветной баннер вверху экрана, который остаётся на месте, пока его
  не закроют вручную (крестиком). Показывается только для по-настоящему
  важных событий:
  - **Админ**: когда приходит новый заказ («¡Nuevo pedido de…!»), и когда
    статус любого заказа меняется НЕ действием этой же вкладки — как
    правило, потому что клиент его отменил, или потому что статус поменяли
    из другой вкладки/с другого устройства. Работает на всех **трёх**
    страницах панели (`/admin`, `/pedidos`, `/ajustes`), а не только на
    Pedidos.
  - **Клиент**: при каждой смене статуса любого из его заказов (включая
    отмену, сделанную самим админом).

Технически:
- У админа `public/js/monitorPedidos.js` (общий для всех трёх страниц)
  опрашивает `GET /api/orders` целиком каждые 15 секунд, сравнивает с тем,
  что уже знал (хранится в памяти, сбрасывается при перезагрузке страницы —
  поэтому не уведомляет о том, что уже существовало на момент открытия),
  обновляет наклейку и показывает уведомление. Страница, которая сама
  вызвала изменение (кнопка статуса или отмена на Pedidos), сразу помечает
  его как «уже увиденное» (`marcarVisto`), чтобы не уведомлять саму себя о
  своём же действии.
- У клиента та же идея — в `tienda.js`, опрос `GET /api/public/mis-pedidos`
  тоже каждые 15 секунд.
- И обычный toast, и яркое уведомление теперь переносят длинный текст на
  несколько строк вместо того, чтобы вылезать за края экрана — раньше у
  toast стояло `white-space: nowrap` без `max-width`, и длинное сообщение
  просто обрезалось краями экрана.

```jsonc

{
  "id": "uuid",
  "nombre": "Bowl de quinoa y pollo",
  "descripcion": "...",
  "precio": 850,                          // в CUP
  "categoria": "almuerzos",

  "disponible": true,
  "porcion": { "valor": 350, "unidad": "g" },  // или null

  "actualizadoEn": "ISO-дата",
```

## API

### Pública (sin autenticación de administrador — la usa la tienda)

| Método | Ruta                      | Acción                                                        |
|--------|----------------------------|----------------------------------------------------------------|
| GET    | /api/public/menu           | Categorías + platos disponibles + tasa de cambio + costo de envío por municipio (todo en una sola respuesta) |
| POST   | /api/public/orders         | Crear un pedido (datos del cliente + municipio + ubicación en el mapa + lista de platos y cantidades) — requiere sesión de cliente (401 sin cuenta) |
| POST   | /api/public/register       | Crear una cuenta de cliente (nombre, email, teléfono, contraseña, dirección opcional) |
| POST   | /api/public/login          | Iniciar sesión de cliente (email + contraseña)                |
| POST   | /api/public/logout         | Cerrar sesión de cliente                                      |
| GET    | /api/public/me             | Datos de la cuenta de cliente actual (o `{ cliente: null }`)  |
| GET    | /api/public/mis-pedidos    | Historial de pedidos del cliente con sesión iniciada          |
| POST   | /api/public/orders/:id/cancelar | Cancelar un pedido propio — solo si sigue en estado `nuevo` (401 sin sesión, 403 si el pedido es de otro cliente) |
| PUT    | /api/public/me             | Cambiar nombre, teléfono y dirección por defecto de la cuenta (el email no se puede editar acá — ni siquiera enviándolo en el body) |
| PUT    | /api/public/me/tema        | Guardar el tema (`oscuro` \| `claro`) de la cuenta de cliente  |

### Administración (protegida por sesión)

| Метод | Путь                          | Действие                                                   |
|-------|-------------------------------|-------------------------------------------------------------|
| POST  | /api/login                    | Войти по паролю (ищется среди всех пользователей)            |
| POST  | /api/logout                   | Выйти                                                        |
| GET   | /api/me                       | Данные текущего пользователя (`usuario`, `tema`)             |
| PUT   | /api/me/tema                  | Сохранить тему текущего пользователя (`oscuro` \| `claro`)   |
| GET   | /api/products                 | Список всех товаров                                          |
| POST  | /api/products                 | Создать товар                                                |
| PUT   | /api/products/:id             | Обновить товар                                               |
| PATCH | /api/products/:id/disponible  | Быстро переключить доступность                               |
| DELETE| /api/products/:id             | Удалить товар (и его картинку)                               |
| GET   | /api/categories               | Список категорий                                             |
| POST  | /api/categories               | Создать категорию                                            |
| PUT   | /api/categories/:id           | Переименовать категорию                                      |
| DELETE| /api/categories/:id           | Удалить категорию (если не используется)                     |
| GET   | /api/settings                 | Получить курс обмена CUP/USD + тарифы доставки по всем 16 провинциям |
| PUT   | /api/settings                 | Обновить курс и/или тарифы доставки (`tasaCup` и/или `enviosPorMunicipio` — можно менять по отдельности, второе поле не стирается) |
| POST  | /api/upload                   | Загрузить изображение (form-data, поле `imagen`, до 5 МБ, сжимается на сервере) |
| GET   | /api/orders                   | Список всех заказов                                          |
| GET   | /api/orders/nuevos-count      | Количество заказов в статусе `nuevo` (для наклейки на кнопке «Pedidos») |
| PATCH | /api/orders/:id/estado        | Сменить статус заказа (`en_preparacion` \| `enviado` \| `completado`) |
| POST  | /api/orders/:id/cancelar      | Отменить заказ в любом статусе кроме `completado` (400, если уже отменён или уже завершён) — версия для админа |
